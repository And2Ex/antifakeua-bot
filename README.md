# AntiFakeUA

**AntiFakeUA** — Telegram-бот для перевірки текстових новин, заяв, дописів із соцмереж і пересланих повідомлень на фейки, маніпуляції та непідтверджену інформацію.

Проєкт створений як відкритий і прозорий інструмент фактчекінгу: користувач надсилає твердження або новину, бот аналізує зміст, шукає підтвердження у відкритих джерелах і повертає короткий зрозумілий висновок.

## Що вміє бот

- перевіряє текстові новини, заяви, переслані повідомлення та дописи;
- визначає, чи є в повідомленні перевірюване фактичне твердження;
- формує відповідь у форматі: **вердикт → короткий заголовок → пояснення → джерела**;
- розрізняє правду, фейк, маніпуляцію, непідтверджену або некоректно подану інформацію;
- кешує повторні перевірки;
- створює публічне посилання на результат перевірки;
- підтримує чергу публікацій і адмінські дії;
- має систему лімітів і платних пакетів перевірок.

## Формат відповіді

Приклад структури відповіді:

```text
✅ Правда

Каховська ГЕС була підірвана, а Великий Луг відновлюється

Пояснення коротко описує, що саме підтверджено, які є джерела і чи є важливі уточнення.

Джерела:
• Джерело 1
• Джерело 2

📌 Оригінальний допис
🔗 Публічна перевірка
```

Після вердикту бот додає короткий заголовок, щоб було зрозуміло, **що саме підтвердилося або не підтвердилося**, навіть без читання всього пояснення.

## Технічний стек

- Python 3.13;
- aiogram 3.x;
- OpenAI API з web search;
- FastAPI для webhook і платіжних callback;
- PostgreSQL через `DATABASE_URL`;
- LiqPay для платних пакетів.

## База даних

Поточна версія використовує **PostgreSQL** замість SQLite.

У базі зберігаються:

- користувачі;
- ліміти;
- кеш перевірок;
- публічні ID перевірок;
- платежі;
- звернення користувачів;
- джерела й службова статистика.

SQLite більше не використовується як основна база, щоб дані не втрачалися після перезапуску сервера.

## Прозорість

AntiFakeUA не має бути «чорною скринькою». Основна логіка перевірки описана відкрито: бот аналізує конкретне твердження, шукає підтвердження, відділяє факти від думок і не робить категоричних висновків, якщо даних недостатньо.

Публічний prompt перевірки доступний у файлі:

```text
docs/PROMPT_PUBLIC.md
```

Методологія описана у файлі:

```text
METHODOLOGY.md
```

## Локальна перевірка підключення до бази

Після створення `.env` з `DATABASE_URL` можна перевірити підключення так:

```powershell
pip install -r requirements.txt
python -m scripts.test_database_connection
```

Очікуваний результат:

```text
OK: connected to PostgreSQL.
Database: ...
Server: PostgreSQL ...
```
